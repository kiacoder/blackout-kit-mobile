## Bounded recovery checkpoint

- The Android service no longer stops the OpenVPN worker on the first disconnected event. The core can reconnect within its existing session, with a 45-second continuous-outage budget measured from the first loss callback, not extended by duplicate down callbacks. An exited, cancelled, stale or expired session is terminal, and a success callback after the deadline cannot restore its connected status. The service polls on its existing 2-second cadence; the deadline is not a real-time packet-filter guarantee. On failure it joins before releasing native ownership and preserves the requested held tunnel only after clean stop. If stop times out, it reports pending cleanup, not a claim of blocking.
- Retains the newly established Android descriptor before closing the previous one or duplicating it for JNI. Flutter receives reconnecting state, suppresses connected uptime/exit identity while recovering, offers cancellation, and can reconcile from native status after reconnect or app reattachment. English, Persian and Chinese labels added.
- Host interoperability now covers explicit core reconnect and a real isolated TCP server stop/restart. Both tests exchange exact TCP and UDP application payloads before and after recovery and require two protected sockets and two TUN establishments. OpenSSL 14/14, pinned Mbed TLS 15/15. ## Custom DNS and per-app routing checkpoint

- OpenVPN receives the existing Android builder-time per-app settings and a distinct optional custom DNS list when DNS protection is enabled. Default mode preserves server-pushed DNS; override mode replaces rather than appends the resolver list. Both pushed and effective DNS must satisfy the existing full-tunnel route admission. The override supports bounded unicast IPv4 literals only; profiles without valid pushed DNS are still rejected. No claim is made that the resolver is reachable on every provider.
- Whitelist mode includes the selected packages plus the Blackout Kit app for tunneled health/exit-IP checks. Blacklist mode rejects excluding the app itself. Mixed or oversized lists and invalid DNS fail closed. Builder package failures are not skipped. Transport sockets continue to use individual protection; there is no general application UID bypass. Split routing intentionally sends excluded apps outside the VPN; it is not system-wide leak protection. The immutable policy is reused for each native TUN rebuild during recovery.
